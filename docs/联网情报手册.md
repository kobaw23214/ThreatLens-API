# 联网情报集成手册

> 面向友商 / 第三方系统的联网威胁情报查询集成指南
> 适用「联网情报调用台」：微步在线（x.threatbook.com）、奇安信（ti.qianxin.com）

---

## 1. 这是什么

本服务在 NER / ATT&CK 提取能力之外，提供 **联网威胁情报查询**：给定 IP / 域名 / 样本哈希，后端以**真实浏览器登录微步在线或奇安信**，把平台页面的原生内容取回，按区块（sections）结构化返回。

与在线查杀 / 沙箱 API 的定位差异：

- **内容是平台页面原生内容**，不是二次加工的判定结论——返回的是"威胁判定、威胁概览、解析域名、相关样本、WHOIS"等页面区块原文，便于直接展示或留档。
- **采集走浏览器会话**（Playwright），需要预先完成平台登录；服务内置极验滑块自动求解与空闲会话保活，登录态失效时会自动重登；自动重登也失败时标记"需人工登录"，此时有两种人工恢复方式（见下文「人工登录 / 会话导入」）：调用台点红灯平台的**「去登录」**在弹出的登录窗口/网页远程桌面里完成一次登录，或点**「导入Cookie」**把本机浏览器已登录的会话 Cookie 粘贴进来。两种方式都会先做数据面验证，通过才接管会话，无需重启服务。
- **反爬纪律**：同一平台任务严格串行、任务间随机间隔 3~8 秒、每平台每日调用上限（默认 5000）、结果缓存 6 小时。这些约束不可绕过，集成方应按"异步、秒级~几十秒级"设计交互。

触发方式与 `/extract` 任务体系一致：**提交任务（202 + task_id）→ 轮询结果或等回调**。

## 2. 快速开始

### 2.1 提交查询任务

```http
POST /ti/expand
Content-Type: application/json
Authorization: Bearer <API_KEY>
```

```json
{
  "seed_type": "ip",
  "seed_value": "8.210.88.161",
  "platforms": ["threatbook", "qianxin"],
  "reuse_cache": true
}
```

**响应**（202 Accepted，每个目标平台一个任务）：

```json
{
  "tasks": [
    { "task_id": "b3f1c2…", "platform": "threatbook", "cached": false },
    { "task_id": "7a9de0…", "platform": "qianxin",    "cached": false }
  ]
}
```

- `cached: true` 表示命中缓存（TTL 内同种子同平台的完成结果），该任务直接可查，不再消耗平台调用。
- 缓存命中时不会生成新任务，`task_id` 指向历史任务。

### 2.2 轮询查询结果

```http
GET /ti/tasks/{task_id}
Authorization: Bearer <API_KEY>
```

任务状态机：`pending`（排队中）→ `running`（采集中）→ `done` / `failed`。
采集耗时通常 **10~40 秒**（受串行间隔与平台页面加载影响），建议轮询间隔 ≥ 2 秒。

```json
{
  "task_id": "b3f1c2…",
  "seed_type": "ip",
  "seed_value": "8.210.88.161",
  "platform": "threatbook",
  "status": "done",
  "sections": [
    { "name": "威胁判定", "format": "text",  "content": "恶意" },
    { "name": "威胁概览", "format": "kv",    "items": { "开放端口": "3", "相关样本": "12" } },
    { "name": "相关样本", "format": "table", "columns": ["样本", "类型"], "rows": [["…", "…"]] }
  ],
  "raw": { "…": "平台接口原始 JSON（可能很大）" },
  "diagnostics": { "channel": "web", "selector_version": "2026-07-25-r4", "duration_ms": 16230 },
  "latency_ms": 16230,
  "created_at": "2026-07-25T10:00:00",
  "finished_at": "2026-07-25T10:00:16"
}
```

## 3. 请求参数

### `POST /ti/expand`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `seed_type` | string | 是 | 种子类型：`ip` / `domain` / `file` |
| `seed_value` | string | 是 | 种子值（格式校验见第 4 节） |
| `platforms` | string[] | 否 | 目标平台子集：`threatbook` / `qianxin`，缺省为全部 |
| `reuse_cache` | bool | 否 | 启用缓存复用（TTL 默认 6h，默认 false；管理员可在管理页「缓存管理 → 联网解析缓存」调整或整体关闭） |
| `callback` | object | 否 | 回调配置，与 `/extract` 同构（`url` / `method` / `headers` / `timeout`） |

**任务列表**：`GET /ti/tasks?page=1&page_size=20&platform=…&status=…`（非管理员仅见自己的任务）。

**会话状态**：`GET /ti/sessions` 返回各平台登录态红绿灯（`ok` / `logging_in` / `need_manual` / `auth_failed` / `expired` / `unknown`）。

**人工登录**（管理员）：`POST /ti/sessions/{platform}/manual-login` → 202 打开平台登录窗口，人工完成登录（扫码 / 密码 / 滑块）；系统用数据面地址实测验证通过后才保存会话（窗口自动关闭、红绿灯变绿）。窗口形态由 `TI_LOGIN_VIEWER` 决定（默认 `auto`）：服务器本机有显示器 → 本机弹窗（`local`）；无显示器（线上 Linux 容器）→ **网页远程桌面**（`vnc`：容器内 Xvfb 虚拟屏跑有头浏览器，画面经 noVNC 搬到网页里），此时 202 响应带 `viewer_url`，前端弹窗内嵌该地址，操作者在**自己的浏览器**里看到服务器浏览器的画面并用鼠标键盘完成登录。已在登录中返回 409（vnc 模式附带 `viewer_url` 供刷新/换机后重新接入）。远程桌面地址用一次性内存票据鉴权（20 分钟过期、随登录进程退出作废），websockify 只绑容器内 127.0.0.1，不额外暴露端口。调用台红灯 chip 上的「去登录」按钮即此接口。

**导入会话 Cookie**（管理员，兜底登录方式）：`POST /ti/sessions/{platform}/import-cookies`，body `{"cookies": <粘贴内容>, "user_agent": "<导出 cookie 的浏览器 UA>"}`。适用场景：远程桌面不可用或需快速恢复——运维在**自己的浏览器**正常登录平台官网（滑块就地过掉），导出 Cookie 粘贴提交。支持三种格式：Cookie-Editor 插件导出的 JSON 数组、Playwright storage_state JSON、Cookie 请求头文本（F12 → Network → 任意请求 → 复制 `Cookie` 整串，可拿到含 HttpOnly 的完整条目；此格式缺 domain 时按平台数据面主域兜底）。服务端注入一次性 headless 浏览器做**数据面探测**，通过才写会话种子并接管（红绿灯变绿），不通过返回 400 且不落盘。`user_agent` 会快照到 `ti_data/sessions/{platform}/imported_ua.txt`，采集端后续同 UA 运行，防平台会话-UA 绑定校验。调用台红灯 chip 上的「导入Cookie」按钮即此接口（前端自动携带当前浏览器 UA）。cookie 即会话凭据：接口仅管理员、不写日志。

**调用统计**：`GET /ti/stats/daily?days=30` 按天/平台/通道统计外部调用量（含 `channel='cache'` 的缓存命中行，命中记 `success_count`，不占日上限）。

**运营指标聚合**：`GET /ti/stats/overview?days=30` 任务统计页「联网解析统计」板块数据源——全量外部调用/成功率/缓存命中、今日调用（分成功/失败）、按平台窗口指标（调用量/成功率/缓存命中率/平均耗时/任务数 + 会话状态 + 日上限）、种子类型分布、近 N 天趋势。平台级口径，不按用户过滤。

**代理配置**（管理员，内网部署出网必经出口机时使用）：管理页「联网解析代理」模块或 `PUT /ti/settings`（`proxy_enabled` 开关 + `proxy_url` 全局 + `proxy_url_<platform>` 平台级覆盖；平台级 > 全局 > 直连，默认关闭）。开关关闭时地址保留不丢；改动下一个任务生效，浏览器自动重建、**会话不丢**；人工登录（去登录）同走代理。地址格式 `http://user:pass@host:port` 或 `socks5://host:port`——**需账密认证请用 http，Chromium 的 SOCKS5 不支持认证**（SOCKS 依赖 `httpx[socks]`）。`GET /ti/settings` 掩码视图不回显 URL 中的账密。保存前可用 `POST /ti/settings/proxy-test` 自检：body 可选 `{"proxy_url": "..."}` 测未保存地址，空 body 按当前生效配置逐平台探测两平台首页，返回 `{proxy, http_status, latency_ms, error}`。

**缓存管理**（管理员）：管理页「缓存管理」分 NER / ATT&CK / 联网解析三类。联网解析缓存的开关与 TTL 独立（`PUT /ti/settings` 的 `cache_enabled` / `cache_ttl`，app_settings 键 `ti.cache_enabled` / `ti.cache_ttl_seconds`，env `TI_CACHE_ENABLED` / `TI_CACHE_TTL` 为初始默认）。`cache_enabled=false` 时 `/ti/expand` 不命中缓存、任务完成也不写入缓存窗口；三类缓存的概览/条目/清理走 `GET|POST /admin/cache/*?category=ner|attack|ti`（不传 category 为提取缓存全量）。后台定时任务会物理删除已过期的缓存任务行（含 TI 任务），`CACHE_CLEANUP_ENABLED` / `CACHE_CLEANUP_INTERVAL` 控制。

**数据导出 / 内网导入**（管理员）：`GET /ti/export?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD` 导出 ti_tasks + ti_task_results 为自包含 SQL 备份（`CREATE TABLE IF NOT EXISTS` + `INSERT ... ON CONFLICT (task_id) DO NOTHING`），在另一套库 `psql -d <目标库> -f <文件>` 幂等加载，重复执行不产生重复行；日期按 ti_tasks.created_at 过滤（含首尾，缺省全量）。**导入即进缓存**：导出文件中 done 任务的 `cache_expires_at` 不写源库原值，改写为 `NOW() + 当前生效 cache_ttl`（在目标库加载时求值）——内网导入的数据默认直接进入缓存复用窗口，同种子 `reuse_cache=true` 的查询直接命中、无需触达外网平台；`ON CONFLICT DO NOTHING` 保证只影响新插入行，目标库已有任务的缓存状态不被改写。导入的任务同时是历史数据，解析详情页按 task_id 随时可查。

## 4. 种子格式与校验

| 类型 | 格式 | 示例 |
|---|---|---|
| `ip` | IPv4 / IPv6 | `8.210.88.161` |
| `domain` | 标准域名 | `fget-career.com` |
| `file` | 32 / 40 / 64 位十六进制（MD5 / SHA1 / SHA256） | `d16918f1…eb86` |

- 格式非法 → **422**。
- 微步的样本报告由云沙箱承载：**SHA256 为完整报告**；MD5 / SHA1 可能只返回"正在分析中"的降级视图（平台机制如此，非采集失败）。

## 5. 结果结构详解

### 5.1 任务响应包络

`GET /ti/tasks/{task_id}` 返回任务对象（**非管理员仅能查看自己的任务**），逐字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | string | 任务 ID，轮询 / 回调唯一定位 |
| `seed_type` | string | 种子类型：`ip` / `domain` / `file` |
| `seed_value` | string | 种子值（IP / 域名 / 文件哈希） |
| `platform` | string | 目标平台：`threatbook` / `qianxin` |
| `channel` | string | 采集通道：`web` = 浏览器采集（当前实现），预留 `api` |
| `status` | string | 任务状态：`pending`（排队中）/ `running`（采集中）/ `done` / `failed` |
| `error_msg` | string | 失败原因（`status=failed` 时给出，否则为 null） |
| `created_at` | string | 任务创建时间（ISO 8601） |
| `finished_at` | string | 任务完成时间（ISO 8601，未完成时为 null） |
| `latency_ms` | int | 采集耗时毫秒（完成前为 null） |
| `callback_status` | string | 回调投递状态（未配置回调时为 null） |
| `user_id` | string | 任务归属用户 ID |
| `information_json` | object | 提交时传入的用户自定义信息，随结果 / 回调原样返回（未传时为 `{}`） |
| `sections` | array | 平台页面区块结构化结果，见 5.2 起 |
| `raw` | object | 平台接口原始 JSON（可能为 null），见 5.5 |
| `diagnostics` | object | 采集诊断信息，见 5.6 |

### 5.2 sections 通用结构

`sections` 为平台页面区块的有序数组，每个元素含 `name`（区块名）、`format` 及对应数据字段。三种 `format` 的精确结构：

| format | 数据字段 | 结构 |
|---|---|---|
| `kv` | `items` | 对象 `{键: 值}`；值为字符串或字符串数组（威胁标签等 chip 类键为字符串数组） |
| `table` | `columns` + `rows` | `columns` 为列名字符串数组，`rows` 为二维数组，**所有单元格均为字符串** |
| `text` | `content` | 字符串（原文文本） |

**通用注意事项**：

- **区块顺序与命名**：区块按平台页面顺序排列（点击类 tab 区块排在默认面板之后），区块名用平台原名叫法；平台改版会引起区块增减，消费端应按 `name` 匹配而非按下标。
- **条件性区块**：部分区块无数据时整块缺席（如微步「用户标签」、奇安信 file「行为明细」「资源信息」）；各区块的条件性标注见 5.3 / 5.4 的总览表与逐区块说明。
- **table 降级为 text**：table / kv 区块在 0 条数据或解析失败（如懒加载超时）时可能降级为 `text`——区块仍在、format 变化。例如奇安信「情报参考标签」0 条时为 text `情报参考标签\n0个辅助研判参考性情报标签`，有数据时为 table。消费端需兼容同一区块两种 format。空态 text 常见内容：`没有数据`、仅区块标题、`…查询中`（懒加载超时）。
- **截断规则**：单表最多 50 行（`_MAX_ROWS=50`；奇安信 file「引擎检测明细」实测恰好 50 行命中截断，真实引擎 100+）；单元格 ≤200 字符（`_MAX_CELL`）；text 区块 ≤8000 字符（`_MAX_TEXT`）；kv 单区块键值元素 ≤60 个；raw 整体超 400KB（`_MAX_RAW`）时，其中任务的 table 截 20 行并打 `_truncated: true` 标记（见 5.5）。
- **页面只渲染首屏**：列表分页、「查看更多」不抓，sections 行数 ≤ 页面首页渲染数；全量数据在 `raw`（见 5.5）。例如奇安信 `ip_passive_dns` raw 有 100 行，而 sections「域名反查」只 5 行。
- **文本拍平**：单元格 / 键值均为页面文本拍平（`innerText`），链接、富文本不保留；多行单元格内嵌 `\n`；空值多为 `-`（奇安信无权限项显示 `*`）。

`raw` 为浏览器响应拦截的平台接口原始 JSON（上限 400KB，超限的内部截断规则见 5.2），**不进回调体**，体积可能很大；需要时用 `GET /ti/tasks/{task_id}` 拉取。

**微步在线（threatbook）**

微步非任务式平台，raw 只有一种顶层形态：仅 `interceptions` 一个键（拦截为空时整个 raw 为 null）：

```json
{
  "interceptions": [
    {
      "url": "https://x.threatbook.com/v5/node/query/basic/ip?resource=8.210.88.161",
      "json": {
        "response_code": 0,
        "verbose_msg": "succeed",
        "data": { "…": "业务负载，结构因接口而异（dict / list / int / str）" }
      }
    }
  ]
}
```

- `interceptions`：list，≤50 条，按 URL 去重（同 URL 轮询只留最后一次）；单条 body >200KB 截断后再解析。
- `json.response_code`：微步业务码，0=成功（部分接口无此层或为 `info` 字段）；`json.verbose_msg`：`succeed` 等（部分接口缺省为 null）。
- 实测条数：ip 任务 34 条（diagnostics.interceptions=36，为去重前计数）；domain 任务 39 条（去重前 41）。
- 全部 URL 均为 `https://x.threatbook.com/v5/node/**` 系列 XHR。
- **file 种子 raw（r9 起）**：file 查询走云沙箱站 `s.threatbook.com`，报告页为 Next.js 静态壳 + 客户端 XHR，数据接口为 `GET /apis/sample/**`（status/summary/signatures2/static/static-embed/multi_engines/memdump/dropped/process/network/{count,dns,domains,http,tcp,hosts}/intelligence/*）与 `/apis/skill/code-insights/{hash}`，URL 带 hash 及沙箱环境后缀（如 `-win7_sp1_e…`）。实测 file 任务 raw.interceptions 29 条（diagnostics.interceptions=31，去重前）。r8 及之前版本未配置拦截、file raw 恒为 null（当时误判该站为 SSR 直出无 XHR，2026-07-26 网络枚举订正，证据 `ti_data/recon/threatbook/s_xhr_log.json`）。

**奇安信（qianxin）**

顶层 3 个键（domain / file 同构，任务集不同）：

**1. `task_map`**（dict，`{任务名: 任务ID}`）——`GET /alpha-api/v2/ti/query` 返回的映射，任务ID 带哈希后缀（每次查询新生成）。实测键数：ip 26、domain 25、file 12。样例（ip）：`{"ip_tag": "ip_tag_cc52ddfac45fa9f3", "ip_cert": "ip_cert_ef74cf2ad4eeb59d", "ip_host": "ip_host_12e206ae41fc8385", "ip_whois": "ip_whois_da014dfd94082628", "ioc_detect": "ioc_detect_a556b943cbec5361", …}`

任务名全集（实测）：

- ip：ip_tag / ip_cert / ip_cert_v2 / ip_host / ip_host_abstract / ip_whois / ip_active / ip_attribute / ip_passive_dns / ip_passive_dns_v2 / ip_c_intelligence / ip_try_connect / ioc_detect / deterministic_tag / referential_tag / reports / reports_v2 / ttp_info / graph_analysis / visualized_analysis / google_search / ip_hunter_info / ip_attack_statis / ip_attacker_info / ip_reputation_his / ip_reputation_his_v2
- domain：dns / whois / whois_v2 / whois_abstract / access / reports / reports_v2 / ttp_info / subdomain / domain_tag / domain_active / domain_trends / domain_attribute / domain_cert_list_v2 / domain_try_connect / domain_passive_dns_a / domain_passive_dns_other / ioc_detect / deterministic_tag / referential_tag / graph_analysis / visualized_analysis / google_search / icp_attribute_his
- file：malfile / md5_tag / reports / reports_v2 / ioc_detect / google_search / cert_detail_v2 / graph_analysis / visualized_analysis / referential_tag / deterministic_tag

**2. `tasks`**（dict，`{任务名: 任务结果体}`）——同一任务 ID 多轮轮询只留最新。每个结果体的键：

| 键 | 类型 | 含义 |
|---|---|---|
| `status` | int | 任务状态码：**10000=完成**（结果在 table / priv_msg），**10303=进行中**（超时收尾时保留，无 table） |
| `priv_msg` | str | 平台附加消息（实测多为空串） |
| `table` | list / dict | 任务结果主数据。**list 形态**：行 dict 数组（全量，不分页）；**dict 形态**：结构化对象 |
| `total_count` / `default_count` | int | 可选，总数 / 默认返回数（如 ip_passive_dns: 100/100） |
| `statistics_map` | dict | 可选，按研判值分桶计数（如 ip_try_connect 的 `{"0":…,"1":…}`，ip_passive_dns 含 `"-1"`） |
| `merge_list` | list | 可选，ip_try_connect / domain_try_connect 的合并样本列表 |
| `_truncated` | bool | 可选，raw 超 400KB 时该任务 table 被截到 20 行并打此标记（实测 2 条旧 domain 任务命中） |

常见任务的 `table` 形态（实测，第 3 层为行 dict 键样例）：

- `deterministic_tag` / `referential_tag` / `ip_tag` / `md5_tag`：list，行键 `name, detail, source, tag_type, valuable, last_seen, first_seen`（ip_tag / md5_tag 另含 `category, tag_source`）——对应 sections 情报研判/参考标签全量。
- `ip_passive_dns`：list[100]，行键 `tags, domain, malicious, time_last, first_seen, days_analysis`——域名反查全量。
- `ip_try_connect` / `domain_try_connect`：list，行键 `md5, action, family, payload, @timestamp, sample_type, malicious_type`——相关样本全量。
- `ip_whois`：dict，键 `ref, rir, cidr, parent, regdate, updated, net_name, net_type, net_range, organization`。
- `ip_host` / `ip_host_abstract`：dict，键 `tags, ports, modules, services, hostnames`。
- `ip_cert_v2` / `domain_cert_list_v2`：dict `{data, total}`。
- `ip_active`：dict `{web_attack, attack_data, statistics_map, resolution_records}`；`domain_active`：list，行键 `tags, count, result, rrtype, time_last, time_first`。
- `dns` / `domain_passive_dns_a`：list，行键 `asn, tags, type/result, record, location, malicious`。
- `whois_abstract`：list[1]，当前 WHOIS（fax/city/name/email/phone/domain/status/address…）；`whois_v2`：list[35]，行键 `fax, name, after, email, phone, before, content, …`（历史注册信息全量）。
- `domain_attribute`：dict，含 `icp, country, popular, industry, latitude, location, last_seen…`（`popular` = 流行度，sections 缺）。
- `google_search`：list[≤10]，行键 `kind, link, title, pagemap, snippet, htmlTitle, displayLink, …`（`link` 即 sections 缺的 URL）。
- `graph_analysis` / `visualized_analysis`：dict `{links, nodes}`（威胁图谱）。
- `malfile`（file）：list[1]，行键 `md5, scan, sha1, trid, crc32, sha256, sha512, sou…`（文件信息全量）。
- `reports_v2`：dict `{msg, data, en_msg}`；`reports`：list（旧版，实测空）。
- 进行中任务（10303）：仅 `status` 一键（如 ip_c_intelligence、ip_passive_dns_v2、subdomain 在抓取时刻未完成）。

**3. `interceptions`**（list[{url, json}]，≤50 条）——全部拦截响应按 URL 去重（轮询只留最后一次）：

- `url`（str）：请求 URL。实测 ip 任务去重后 10 条（`ti/query?…execute=1`、多条 `ti/task/{id,id,…}` 轮询、`user/ioc-status?ioc_name=…`、`case/clues?…value=…`）。
- `json`（dict）：响应体。ti API 统一包裹 `{status, message, data}`——`data` 对 query 是 `{任务名: 任务ID}`，对 task 轮询是 `{任务ID: 结果体}`；**例外** `case/clues` 返回 `{page, objects, num_results, total_pages}` 分页结构（无 status 包裹）。

### 5.6 diagnostics 结构

实测样例（微步 ip 任务）：`{"channel":"web","session":"verified","artifacts":[],"duration_ms":31885,"interceptions":36,"selector_version":"2026-07-25-r6"}`

| 键 | 类型 | 含义 |
|---|---|---|
| `channel` | str | 采集通道，web 适配器固定 `web` |
| `session` | str | 会话来源：`verified` = 本次探测/重登验证过；`cached` = 10 分钟缓存期内复用 |
| `artifacts` | list | 失败留证（截图/HTML 路径）清单；成功任务恒为 `[]` |
| `duration_ms` | int | 单次查询耗时毫秒（微步实测 13s~35s，file 页面无拦截等待、耗时更短；奇安信实测 33883~47233） |
| `interceptions` | int | 拦截到的 XHR 条数（**去重前**；`raw.interceptions` 为按 URL 去重后、≤50）。微步 file 任务为 0；奇安信实测 ip/domain 26、file 3 |
| `selector_version` | str | 采集所用 selector 版本（如微步 `2026-07-25-r6`、奇安信 `2026-07-25-r7`），平台改版排查用 |

## 7. 约束与错误码

| 场景 | 状态码 / 表现 | 说明 |
|---|---|---|
| 种子格式非法 | 422 | 不生成任务 |
| 平台队列已满（默认 50） | 503 | 稍后重试 |
| TI 服务未启用 | 503 | `TI_ENABLED=false` |
| 平台日调用上限（默认 5000） | 任务 `failed` | 成功+失败都计数，防失控重试 |
| 会话失效 / 需人工登录 | 任务 `failed`，`GET /ti/sessions` 红灯 | 调用台点红灯平台「去登录」（无显示器服务器走网页远程桌面），或「导入Cookie」粘贴本机浏览器已登录的会话；对应接口 `POST /ti/sessions/{platform}/manual-login` / `import-cookies` |
| 平台页面改版 | 任务 `failed`（selector 未取到内容） | 联系维护方校准 selector |
| 采集超时（默认 120s） | 任务 `failed` | 平台页面加载过慢 |

**集成建议**：

- 按**异步任务**设计，不要同步等待；优先用回调。
- 同一批种子建议带 `reuse_cache: true`，6h 内重复查询零成本。
- 批量提交时注意每平台串行执行 + 3~8s 间隔，吞吐约 **450~900 次/平台/小时**，日上限内规划总量。

```python
import time
import requests

BASE = "http://<host>:8036"
HEADERS = {"Authorization": "Bearer <API_KEY>"}

resp = requests.post(
    f"{BASE}/ti/expand",
    json={"seed_type": "domain", "seed_value": "example.com", "reuse_cache": True},
    headers=HEADERS,
    timeout=10,
)
resp.raise_for_status()
tasks = resp.json()["tasks"]

for t in tasks:
    while True:
        time.sleep(2)
        r = requests.get(f"{BASE}/ti/tasks/{t['task_id']}", headers=HEADERS, timeout=10).json()
        if r["status"] in ("done", "failed"):
            break
    print(t["platform"], r["status"], [s["name"] for s in r.get("sections", [])])
```
