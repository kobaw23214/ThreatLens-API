# 文件解析手册

> 第三方如何向平台上传文件做实体/IOC 提取
> 涉及端点: **`POST /extract/upload`**(文本/PDF)、**`POST /extract/eml`**(邮件)

---

## 1. 概述

平台除了直接提交文本(`POST /extract`)外,还支持上传文件。服务端先把文件解析/转换为纯文本,再交给与 `/extract` 完全相同的异步提取管线(任务队列 → 模型推理 → 结果查询),因此**结果查询、缓存复用、回调机制三个端点全部通用**。

```
文件上传
  → 校验(大小 / 扩展名白名单 / 二进制嗅探)
  → 按格式解析为文本:
       文本类  → 多编码自动识别后直接作为输入
       PDF    → PyMuPDF 提取文字层
       EML    → mail-parser 解析为结构化 JSON → 展平为文本
       MSG    → extract-msg 解析为结构化 JSON → 展平为文本
  → 实体/IOC 提取(模型由 model_name 指定)
  → GET /tasks/{task_id}/result 查询结果
```

### 1.1. 两个上传端点怎么选

| 端点 | 适用文件 | 特点 |
|------|----------|------|
| `POST /extract/upload` | 纯文本类、PDF | 通用入口;`labels` 必填;解析出的文本替代 JSON 接口的 `text` 字段 |
| `POST /extract/eml` | `.eml` / `.msg` 邮件 | 邮件特化:`labels` 可留空(内置 IOC 标签集);默认 `ioc-finder` 模型;**完整邮件解析 JSON 随结果返回**(`information_json.eml`) |

> 通用规则:单文件大小上限由环境变量 `UPLOAD_MAX_BYTES` 控制,默认 **10 MB**;超限返回 400。

## 2. 支持的文件格式与解析方式

### 2.1. 纯文本类(`/extract/upload`)

支持的扩展名：

```
.txt  .md  .markdown  .rst  .log  .csv  .tsv
.json  .jsonl  .ndjson  .xml  .yaml  .yml  .ini  .cfg  .toml
.html  .htm  .srt  .vtt
```

**解析方式——四道校验防线**(任一失败返回 400)：

1. **非空 & 大小限制**:空文件或超过 `UPLOAD_MAX_BYTES` 直接拒绝
2. **扩展名白名单**:仅上表所列扩展名
3. **二进制特征检测**:读取文件头 4 KB,出现 NULL 字节、或非打印控制字符占比 > 30% → 判定为二进制文件拒绝(把 PNG 改名成 `.txt` 也会被识别)
4. **编码自动识别**:依次尝试 UTF-8(含 BOM)→ UTF-16(含 BOM)→ GB18030(覆盖 GBK/GB2312)→ Latin-1 兜底

解码后的文本直接作为提取输入,后续分块(`chunk_*` 参数)、`label_mapping`、缓存、回调与 `/extract` 一致。

### 2.2. PDF(`/extract/upload`)

**解析方式**:使用 PyMuPDF(`fitz`)按页提取**原生文字层**并拼接。

- 电子版 / 可复制文字的 PDF → 正常提取
- **扫描件 / 纯图片 PDF(无文字层)→ 提取结果为空,返回 400**。平台不做 OCR
- 加密且需要密码的 PDF → 返回 400

PDF 走独立分支,不参与文本编码解码和二进制嗅探。

### 2.3. 邮件(.eml / .msg,`/extract/eml`)

**解析方式**:`.eml` 使用 [SpamScope/mail-parser](https://github.com/SpamScope/mail-parser)(Apache 2.0),`.msg`(Outlook OLE2 格式)使用 [extract-msg](https://github.com/TeamMsgExtractor/msg-extractor)(GPLv3);两者输出同一结构的邮件 JSON,再把关键字段展平为文本进入提取管线。特点：

- **完整头部解析**:全部邮件头(含 `Authentication-Results`、`Received`、`X-*` 自定义头)纳入提取范围
- **Received 逐跳链路**:每一跳的 `from` / `by` / `with` / `date_utc` 单独成行,发信源 IP 不丢失
- **附件元数据**:文件名、content-type、大小、**SHA-256**(payload 只在内存中解码算哈希,不落盘、不随响应返回——恶意附件样本可安全提交分析)
- **缺陷检测**:RFC 违规 / 畸形 MIME 结构(`defects` 字段),可作为邮件可疑度信号
- **defang 还原**:配合 ioc-finder / iocextract,`hxxp://`、`evil[.]com` 等钓鱼邮件常见写法可被还原提取

详见第 4 章。

## 3. 通用上传示例

### 3.1. curl

```bash
# 文本文件
curl -X POST "http://localhost:8036/extract/upload" \
  -F "file=@report.txt" \
  -F 'labels=["人物","地点","URL","邮箱"]' \
  -F "model_name=gliner-x-large"

# PDF(同样走 /extract/upload)
curl -X POST "http://localhost:8036/extract/upload" \
  -F "file=@CISA_report.pdf" \
  -F 'labels=["IP地址","域名","URL","哈希","CVE"]' \
  -F "model_name=ioc-finder"

# EML / MSG(走专用端点,labels/model_name 可留空)
curl -X POST "http://localhost:8036/extract/eml" \
  -F "file=@phishing.eml"

curl -X POST "http://localhost:8036/extract/eml" \
  -F "file=@phishing.msg"
```

### 3.2. Python(requests)

```python
import time
import requests

BASE = "http://localhost:8036"
HEADERS = {"X-API-Key": "<your-api-key>"}   # 认证见《提取标签 API 手册》第 3 章

def submit_and_wait(endpoint: str, filepath: str, **form):
    with open(filepath, "rb") as f:
        r = requests.post(endpoint, files={"file": f}, data=form,
                          headers=HEADERS, timeout=30)
    r.raise_for_status()
    task_id = r.json()["task_id"]
    while True:
        res = requests.get(f"{BASE}/tasks/{task_id}/result",
                           headers=HEADERS, timeout=30).json()
        if res["status"] == 1:
            return res
        if res["status"] == -1:
            raise RuntimeError(res["msg"])
        time.sleep(1)

# PDF + ioc-finder
res = submit_and_wait(
    f"{BASE}/extract/upload", "CISA_report.pdf",
    labels='["IP地址","域名","URL","哈希","CVE"]', model_name="ioc-finder",
)
for e in res["entities"]:
    print(f"[{e['label']}] {e['text']}")

# EML / MSG(全部默认)
res = submit_and_wait(f"{BASE}/extract/eml", "phishing.eml")
eml = res["information_json"]["eml"]
print("主题:", eml["subject"], "| 附件:", [a["filename"] for a in eml["attachments"]])
```

## 4. 邮件解析详解(.eml / .msg)

### 4.1. 处理链路

```
.eml 文件 → mail-parser ┐
                          ├→ 解析为结构化 JSON(头部 / Received 链路 / 正文 / 附件元数据)
.msg 文件 → extract-msg ┘
  → 关键字段展平为纯文本(作为提取输入 input_text)
  → 复用异步任务队列做实体/IOC 提取(默认 ioc-finder 模型)
  → 任务结果:实体列表 + information_json.eml 中的完整邮件 JSON
```

> `.msg` 为 Outlook OLE2 二进制格式,通常没有 RFC822 传输头部;仅当文件内嵌了
> 传输头部(`PR_TRANSPORT_MESSAGE_HEADERS`)时,`headers` / `received` 字段才有内容。

### 4.2. 表单字段(`POST /extract/eml`)

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file` | file | 是 | `.eml` / `.msg` 邮件文件,大小上限同 `UPLOAD_MAX_BYTES` |
| `labels` | string (JSON) | 否 | 实体标签 JSON 数组字符串。**留空使用内置 IOC 标签集**(见 4.3) |
| `model_name` | string | 否 | 默认 `ioc-finder`。可指定任意已加载模型(如 `iocextract`、`auto`、`gliner-x-large`) |
| `reuse_cache` | boolean | 否 | 是否启用缓存复用,同 `/extract` |
| `information_json` | string (JSON) | 否 | 用户自定义信息;服务端会注入 `eml` 键存放邮件解析 JSON |
| `callback` | string (JSON) | 否 | 回调配置,同 `/extract` |

> 该端点**不支持** `label_mapping` 与分块参数(`chunk_*` / `threshold`):邮件展平文本由确定性引擎整体处理,无需分块。

### 4.3. 内置默认标签集

`labels` 留空时等价于传入：

```json
["邮箱", "域名", "URL", "IP", "IPv6", "MD5", "SHA1", "SHA256", "SHA512",
 "CVE", "比特币地址", "MAC地址", "文件路径", "CIDR", "ASN"]
```

标签含义与别名规则见《ioc-finder 模型手册》第 2 章。需要语义型实体(人物/组织等)时,改用 `model_name=auto` 或 GLiNER 模型。

### 4.4. 邮件解析 JSON 结构(information_json.eml)

```json
{
  "eml": {
    "format": "eml",
    "filename": "phishing.eml",
    "eml_sha256": "原文件的 SHA-256(.msg 时为 msg_sha256)",
    "subject": "邮件主题(已解码 encoded-word)",
    "from": [["显示名", "sender@example.com"]],
    "to": [["", "rcpt@example.com"]],
    "cc": [],
    "reply_to": [],
    "date": "2020-04-21T14:05:44+00:00",
    "timezone": "+5.0",
    "message_id": "<DC242514.A7EC8559@hotmail.com>",
    "headers": { "Received": "…", "Authentication-Results": "…", "X-…": "…" },
    "received": [
      {
        "hop": 1, "from": "[192.168.0.4]", "by": "mail.example.com",
        "with": "ESMTP", "date": "Tue, 21 Apr 2020 19:26:00 +0500",
        "date_utc": "2020-04-21T14:26:00+00:00", "delay": 0
      }
    ],
    "to_domains": ["example.com"],
    "body": "正文全文(text_plain + text_html 原文)",
    "text_plain": ["纯文本正文 part 列表"],
    "text_html": ["HTML 正文 part 列表"],
    "attachments": [
      {
        "filename": "invoice.pdf",
        "mail_content_type": "application/pdf",
        "content_transfer_encoding": "base64",
        "content_disposition": "attachment; filename=\"invoice.pdf\"",
        "size": 12345,
        "sha256": "附件解码后的 SHA-256"
      }
    ],
    "has_defects": false,
    "defects": []
  }
}
```

字段要点：

- **`format`**:`eml` / `msg`,标识来源文件格式(.msg 时 SHA-256 字段名为 `msg_sha256`)
- **`from` / `to` / `cc` / `reply_to`**:`[[显示名, 地址], ...]` 列表(显示名可为空串)
- **`received`**:按跳序排列;`from` 常含发信方 IP(形如 `[192.168.0.4]`),是溯源关键字段
- **`attachments`**:**不含 payload**,仅元数据 + SHA-256,供外部系统(威胁情报库、沙箱)比对
- **`defects`**:RFC 违规列表(如畸形 MIME 边界),攻击邮件常借此隐藏 payload,非空时应提高警惕

### 4.5. 展平文本布局(input_text)

实体的 `start` / `end` 偏移对应 `input_text`,其布局为：

```
Subject: <主题>
From: <显示名 <地址>>
To: / Cc: / Reply-To: / Date: / Message-ID: …
<全部原始头部,每行一个 Key: Value(含 Received / Authentication-Results / X-*)>
Received-Hop: hop=1 from=[192.168.0.4] by=mail.example.com with=ESMTP …   ← 每跳一行
Received-Hop: …

<正文(text_plain + text_html 原文,HTML 中的 URL 一并保留)>

Attachments: invoice.pdf, readme.txt                                      ← 附件文件名列表
```

> 头部 dict 会折叠重复的 `Received` 头,`Received-Hop` 行保证完整链路进入提取范围。

### 4.6. EML 限制

- **仅支持 `.eml`**(RFC 822);Outlook `.msg` 请先转换为 EML 再上传
- **附件内容不做二次分析**(不解压、不查毒、不提取附件内文本)
- 前端入口:NER 调用台 → 「上传文件」标签页直接拖入 `.eml` 即可(自动走 `/extract/eml`)

## 5. 错误码一览

| HTTP | detail | 原因 |
|------|--------|------|
| 400 | `上传文件为空` | 空文件 |
| 400 | `上传文件过大 (N 字节),上限 M 字节` | 超过 `UPLOAD_MAX_BYTES` |
| 400 | `不支持的文件类型 '.xxx'…` | 扩展名不在白名单(`/extract/eml` 仅 `.eml`) |
| 400 | `文件内容看起来不是纯文本(检测到二进制特征)…` | 二进制文件伪装成文本格式 |
| 400 | `文件解码失败: …` | 文本编码无法识别 |
| 400 | `未能从 PDF 中提取到文字…` | 扫描件/纯图片 PDF(无文字层) |
| 400 | `PDF 已加密,需要密码…` / `PDF 解析失败…` | 加密或损坏的 PDF |
| 400 | `未能从文件中解析出邮件内容,请确认是合法的 EML 文件` | 内容不是有效邮件 |
| 400 | `模型 'xxx' 未加载` | `model_name` 指定的模型未启用 |
| 422 | `labels 必须是非空字符串数组` | labels 字段非法(`/extract/upload` 必填) |
| 422 | (FastAPI 默认) | 缺少 `file` 字段 |
